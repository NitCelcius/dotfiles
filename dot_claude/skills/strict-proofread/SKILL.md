# 厳密な校正ルール

文章の添削・校正であることが明示されたときに使う。軽い推敲は、このスキルを使わず通常の応答の中で行う。(A) 校正の進め方と出力形式、(B) 校正時に能動的に探す文体チェックリスト、を定める。

## A. 校正の進め方 (プロセス)

- 指示がない限り、**変更前に「変更箇所 (変更前後と周辺) と理由」を提示する。承認されるまで本文を編集してはならない。**
- 2フェーズで運用する。
  - **議論フェーズ**は差分だけを見せる (clean な全文は出さない)。
  - **反映フェーズ**は approve されたときだけ。修正後フルテキストをプレーンなコードブロックで出す (ワンタップコピー用、前置き記号を入れない)。出力後に元の語が欠けたり壊れたりしていないか必ず読み返す。
- 校正案には、分類をまたいで一意に指せる通し番号を問題ごとに振り (分類の記号を添えてよい。例 動1・名2・書3)、選択肢には問題をまたいで重複してよい短い記号 (A/B/...) を振る。案を複数出すときも、**どの番号を適用するかを選択式アンケートで聞いてはならない**。承認は自由記述で受ける (例「全部」「2以外」「1: A, 3: Z」)。現状維持の選択肢は Z とする。返答のない番号は適用せずに聞き直す。優先度に差があるときは、テーブルや本文で優先度を明示するにとどめる。
- 変更を反映したら結果を簡潔に報告する。

## 差分の出し方

変更が **少ない** ときは diff のコードブロックで示す。削除する行は `-`、追加する行は `+` で始める。

```diff
-調整力です——メンバーの
+調整力です。メンバーの
```

変更が **多い** ときは通し番号つき変更点テーブル。

| # | 原文 | 修正案 | 理由 |
|---|---|---|---|
| 1 | 本質的な価値がある | 誤差が 3% 小さい | 説明し切れない大きな価値語を数値に置き換え |

- 変更箇所だけを差分で示し、変えない地の文はそのまま書く。
- 段落単位で大きく書き換えるときは、テーブルではなく `変更前 / 変更後` の2ブロックで並べてよい。
- 承認後のフルテキストは、差分の記号 (行頭の `-` `+` や `~~`) を必ず外した状態で出す。

## B. 校正時チェックリスト

凡例。【常時】は作文全般で必ず、【文脈】は技術文書・要旨・write-up など該当時のみ。

### 表現・レトリック

- 【常時】比喩・たとえ・キメセリフ・キャッチー表現を使わない。事実と論点をプレーンに書く。
- 【常時】説明し切れない大きな価値語 (例「本質的な価値」) を使わない。
- 【常時】唯一解めいた断定 (例「欠かせない」) を避け、複数手段の一つとして書く。
- 【常時】語り口調・詩的・独白調 (例「〜したい。」) にしない。説明的・断定的に書く。
- 【常時】倒置強調「〜なこと。それが…だ」を使わず1文で言い切る。

### 記号・語彙

- 【常時】ダッシュ記号 (——, —, –, ―) を使わない。文を分けるか読点・接続詞でつなぐ。
- 【常時】必要でない英単語を途中に挟まない。日本語だと不正確・不自然になる技術用語・固有名詞のみ例外。
- 【常時】全角コロンを使わない。全角カッコより半角カッコを優先する (引用・コード・固有名詞は原文を尊重する)。
- 【常時】大学1年生に説明する程度の平易な語彙にする。専門語・略語は必要なとき以外使わない。ただし噛み砕きすぎない。

### 数値・比較

- 【常時】「上回る/下回る」の多義を避ける。比較する指標 (誤差・RMSE など) を主語に立て、「〜の誤差が小さい/大きい」「値として〜を下回る/上回る」のように一意に読める表現にする。

### 表記の一貫性

- 【文脈】同じ対象を指す語と書式を、文書全体でそろえる。動詞、名詞、書式の順に探す。
  - 同じ動作や概念に複数の語があるときは、1つに寄せるか、使い分けの基準を1つ決める (例「すべて/全て」)。
  - 公式の名称があるものは、公式の名称にそろえる。
  - 述語は、実際に起きたことや測ったことに合わせる。
  - 指摘するときは、該当箇所の前後の文を引用し、揺れている語を太字にする。
- 【常時】数字と和語の間、inline code と和語の間、カッコの前の空白の有無を、文書の中でそろえる。
- 【文脈】表の見出しには単位を付け、セルでは見出しにある語をくり返さない。
- 【文脈】表の列や行が数値のときは、その見出しを何の量かが分かる名詞にする (例「回数/分」より動作の対象が分かる「質問数/分」、「最大・最小」より「最大値・最小値」)。
- 【文脈】単位の書き方と表の区切り行を、文書の中でそろえる。

### 技術文書・要旨・write-up

- 【文脈】手法名を略さず正式名称で書く (例「三次」ではなく「三次畳み込み内挿法」)。
- 【文脈】要旨では見出しブロックを使わず、隅付き括弧の連結ラベルなどインラインで示す。予稿・技術文書全般への一般化は都度確認する。
- 【文脈】原理重視・事例控えめ・指定字数厳守。
- 【文脈】識別子とコードの変数・関数・式は inline code でくくる。式単位でくくると markdown のエスケープも減る。

## 他skillとの接続

- **発表原稿や口頭台本を校正するとき**は `seshi-presentation-voice` を自動で併用する。向こうが話し言葉の文体を決め、本skillが差分提示・承認・反映の手順を決める。両者が衝突する場合は、口頭で自然に話せることを文体判断に使い、本skillの承認手順は維持する。
- **画像から忠実に文字化した直後の文章は自動で校正しない。** 原文との対応を保ったまま文字化を完了し、別工程として校正するかを提案する。
- **yomiyasu-seshi は別のスキル。** 比喩・主述関係・構文を、意味を変えずに読みやすく書き直す。本人が明示的に呼んだときだけ動く。本スキルは自動で併用せず、書き直しが必要そうなときは、本人が呼ぶ選択肢として一言伝えるにとどめる。
