# Knowledge(s) の大ジャンル・中ジャンル・Description を埋める

Notion AI の自動入力 (AI プロパティ) の代わり。Knowledge(s) の各ページを読み、空になっている3つのプロパティだけを埋める。

## 対象

- データソース `collection://ebb90a48-79c1-43bf-903c-5c1c192051ab` (Knowledge(s))
- ページの URL を渡されたときは、そのページだけを対象にする
- 渡されないときは、大ジャンル、中ジャンル、Description のどれかが空の行すべてを対象にする
- 値が入っているプロパティは上書きしない。空のプロパティだけを埋める

## 手順

1. 同じフォルダの `schema.md` を読み、大ジャンルと中ジャンルの選択肢を取る。選ぶ数は下の「値の規則」に従う。update-page が選択肢を受け付けないときは、schema.md の内容が DB とずれているので、データソースを fetch して差分を報告する
2. 対象の行を集める。URL を渡されていなければ、query-data-sources で3つのうちどれかが空の行を引く
3. 各ページを fetch し、タイトル、URL プロパティ、本文を読む
4. 下の規則で値を決める
5. update-page でプロパティを書き込む。大ジャンルと中ジャンルは複数選択なので、選択肢名の JSON 配列 (例 `["テクノロジー", "学習・キャリア"]`) で渡す
6. 最後に、ページごとの書き込んだ値の一覧を返す。判断できずに空のまま残したページは、理由を添えて別に挙げる

## 値の規則

### 大ジャンル

- 選択肢から、ページの内容に合うものを1つか2つ選ぶ。3つ以上は付けない
- 選択肢にない値は作らない

### 中ジャンル

- 選択肢から、ページの内容に合うものをすべて選ぶ
- 選択肢にない値は作らない

### Description

読み返したときに本文を開かずに要点が分かる TL;DR として、日本語で書く。

- `- ` で始まる箇条書きを3〜5行にする。1行は1文で、句点を付けない
- 1行目は何の記事、投稿、資料かと、いつ、誰が、何をしたかを書く。「〜の記事で」「Xユーザーが」のように、文書そのものや出典に触れてよい
- 2行目以降は、具体的な事実 (数値、日付、固有名詞、手順、条件) を1つずつ書く。抽象的な言い換えより、本文にある具体を優先する
- 最後の行は、今後の見通しや、この情報をどう使えるかを書いてよい。本文に根拠がなければ書かない
- 本文にない情報を足さない

構成の手本 (Knowledge(s) の既存ページから)。

```
- Infracost は Terraform コードの変更に伴うクラウドコスト増減を事前に算出できるツールである
- プルリクエストに月額コスト変動とガバナンスチェックの結果を自動コメントで提示する
- コスト変化は infracost コマンドでローカルまたは CI 上で計算できる
- コメントは増減額と合否情報を含み、レビュー時の意思決定を支援する
- 2026年8月30日に公開され、GitHub リポジトリでソースが管理されている
```

### 内容が足りないとき

- 本文が空、またはタイトルと URL だけで内容を判断できないときは、大ジャンルと中ジャンルを空のまま残す
- 本文が完全に空のときは、Description に「内容なし」と書く

## 注意

- Notion への書き込みはプロパティの更新だけにする。本文やタイトルは変更しない
- 件数が多いときは10件ずつ処理し、区切りごとに進み具合を出力する
